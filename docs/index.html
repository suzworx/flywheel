Own the factory. Rent the agents and the intelligence.

A dark factory for AI coding work. The factory — work orders, gauges, the event log, its memory — is files you own. Agents and models are rented from any vendor and swapped at will.

Download a release View on GitHub

The idea

Cheap, disposable agents do the building. Deterministic gauges check every claim they make. One expensive frontier lead makes only the calls that need judgement.

A worker's word is never evidence. Every unit of work declares up front which files it owns and which commands must pass; the CLI re-runs those commands itself, on the exact tree that was produced, and records the reading in an append-only event log. A unit that cannot show a passing reading cannot be accepted — not by convention, but because the tool refuses.

The loop

01 · LEADPlanA brief declares owns:, needs: and one gate: per check. flywheel lint catches a bad one before anyone is dispatched.
02 · WORKERBuildflywheel run dispatches a rented agent into its own worktree and streams every tool call into the run log.
03 · GAUGESMeasureflywheel validate re-runs each gate and checks the owns boundary. The worker's own green is never trusted.
04 · LEADLandflywheel inspect applies the poka-yoke rules and refuses anything unproven. Only then does the work land.

What makes it different

Gates you cannot talk your way past

A rule refusal exits 6. A pass verdict without a matching passing reading on the same tree hash is refused outright, so "it works on my machine" has nowhere to live.

live-gate: — the mock cannot vouch for the contract

A gate that runs only in the lead's verification pass, against the real provider. A unit that declares one cannot be accepted on mocked gates alone.

An append-only ledger

Every plan, dispatch, reading, verdict and landing is an event. flywheel verify checks the whole chain; flywheel trace replays everything one session did.

Any vendor, swapped at will

Adapters for OpenCode, Claude Code and an offline simulator. flywheel doctor probes every configured model and tells you which ones are actually usable.

Install

# download the asset for your platform from the latest release, then verify it
gh release download --repo suzworx/flywheel --pattern '*checksums*' --pattern '*linux-amd64*'
sha256sum -c --ignore-missing checksums.txt
unzip flywheel-*-linux-amd64.zip && sudo install flywheel-* /usr/local/bin/flywheel

flywheel version
flywheel init          # scaffold the factory into a repo
flywheel doctor        # check every configured model is usable

Go 1.27, standard library only — no dependencies, one static binary. Linux, macOS (Intel and Apple silicon) and Windows.

A few commands

CommandWhat it does
flywheel initScaffold the factory state files into a repo.
flywheel lintCheck a brief for a missing owns, a missing gate, or a live-gate that only repeats a mocked one.
flywheel runDispatch a worker for a task and record everything it does.
flywheel validateRe-run a task's gates and check its owns boundary. --live adds the real-path gates.
flywheel inspectApply the poka-yoke rules and record a verdict.
flywheel factoryLive dashboard of the floor, with an andon for units that have stalled or gone quiet.
flywheel doctorProbe every configured model and classify its availability.
flywheel feedbackCurate signals into learnings, and regenerate learnings.md.

It builds itself

flywheel is developed through its own loop: briefs are written, rented workers build, the CLI measures, and the lead lands only what the gauges will vouch for. Pointing the factory at itself is also how several of its own defects were found — including a worker path where a failed run was being recorded as a clean success.
